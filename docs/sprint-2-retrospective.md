# Sprint 2 Retrospective

## What went well

- The two Sprint 1 actions were done first: a test that drives the console menu, then a status line and one `LOG` line per action.
- Complete and delete were small once add and list existed. Each one has its own commit and a test.
- Three classes were enough. `Todo` holds one task, `TodoList` stores them, and `TodoApp` is the menu.

## What to improve next time

- Keep the first version a console menu. A web server was more structure than this prototype needed.
- US-06 (filter by status) is still open. It can wait until the list is saved somewhere that survives closing the app.

## Lesson

A short sprint goal, a test that runs the real menu, and a status line were enough. The useful change from Sprint 1 to Sprint 2 was testing the menu the user sees and logging each action.
